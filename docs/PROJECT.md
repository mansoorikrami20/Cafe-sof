Состояние зафиксировано 22 октября 2026 года. Пользователь — Mansoor Ikrami. Основной язык интерфейса и общения — русский. Заказчик уже одобрил визуальный стиль меню по референсу DashBite. Сервис Smartofood исключён, развиваем собственную систему.

## Требования клиента

1. Четыре филиала/франшизы, в каждом своя iiko и доставка.
2. Единый главный каталог блюд с назначением ассортимента каждому филиалу. Название филиала, адрес, телефон, часы и интеграция настраиваются отдельно.
3. Возможность скрыть блюдо или поставить его в стоп-лист только в одном филиале.
4. QR-ссылка на меню конкретного филиала.
5. Отдельный каталог продуктов; посетитель может заказать еду и продукты. Правила совместной корзины и отправки позиций согласовать при реализации.
6. Базовые часы работы 09:00–00:00 с настройкой каждого филиала. Завтраки доступны до 11:00 по времени Москвы; сервер должен проверять доступность при создании заказа.
7. В исходнике указано «от 1000р доставка». Требует уточнения: минимальная сумма заказа, бесплатная доставка от этой суммы или другой смысл. Не подставлять 1000 ₽ в стоимость доставки.
8. Владелец редактирует меню без разработчика. Данные должны сохраняться на сервере и обновляться у посетителей.
9. Нужны клиенты: имя, подтверждённый телефон, адреса и история заказов; заказы: состав, филиал, доставка/самовывоз/стол, сумма, оплата и статусы.
10. Нужны настройки iiko на уровне филиала: проверка подключения, организации/терминальные группы, импорт меню, цены, стоп-лист, доставка заказов и ошибки синхронизации.
11. Для продуктов: категории, фото, единицы шт./кг/л, цены, наличие/остатки и доступность по филиалам. Ассортимент и цены продуктов ещё не предоставлены.

## Источники меню

`docs/sources/menu-prices.txt` — основной источник актуальных цен. В проектном чате пользователь отдельно подтвердил: TXT приоритетнее PDF. При расхождениях переносить цену из TXT, не из изображения.

Предоставлен PDF `Sof-menu-generated-A4-300dpi(1).pdf`: 11 страниц A4, изображения без извлекаемого текстового слоя. Он остаётся у пользователя в материалах проекта и не включён в Git-импорт. Не считать PDF доступным в новом сеансе Codex, пока его явно не приложили или не добавили. Текущие используемые оптимизированные фотографии уже находятся в `dist/assets/`.

Не добавлять фальшивую фотографию отсутствующего блюда: использовать предусмотренную нейтральную заглушку до получения фото. В TXT есть неоднозначные строки (например, отдельная «баранина 450р»); не превращать их в выдуманные позиции без подтверждения.

2. Завершить активацию существующей админки и проверить серверное сохранение с двух независимых сеансов.

6. Реализовать iiko-адаптеры и настройки по филиалу: секреты на сервере, проверка подключения, сопоставление ID, контролируемый импорт, синхронизация, журнал ошибок. Чётко определить источник цены, чтобы импорт не стирал ручные правки без выбранного правила.

## Изменения разработки 22 октября 2026 года

- Добавлена схема каталога версии 2. Старые каталоги и резервные копии читаются с безопасными значениями по умолчанию; существующие блюда и ручные цены не заменяются. После сохранения новой схемы старый клиент должен обновить страницу (иначе сервер вернёт 409).
- Первоначальный каталог содержит 45 позиций и варианты порций из TXT. Строка «баранина 450р» не импортирована как самостоятельное блюдо. Для уже сохранённого каталога кнопка «Добавить недостающие блюда из TXT» добавляет позиции в черновик, сохраняя существующие цены; затем требуется явное сохранение владельцем.
- Четыре филиала изначально скрыты и без выдуманных контактов. Включение требует названия и адреса. Владелец назначает ассортимент каждой позиции, отдельные цены, видимость, наличие, для товаров — остаток. Без назначения позиция не показывается в меню выбранного филиала. Общий стоп-лист и скрытие имеют приоритет.
- Время работы по умолчанию 09:00–00:00, завтраки до 11:00 по Москве. API каталога делает завтраки недоступными с наступлением отсечки. Будущий API заказов должен повторно проверять время, цену, остатки и филиал на сервере; сейчас API заказов отсутствует.
- Фотографии товаров используют тот же защищённый private Blob, что и фотографии блюд. Товарные цены, ассортимент, составы и контакты владелец заполняет самостоятельно. Нулевой остаток делает товар недоступным; пустой остаток означает «не указан», не бесконечный подтверждённый запас. Автоматическое резервирование/списание не реализовано.
- Каталог филиала доступен по `/?branch=branch-N`, API — `/api/catalog?branch=branch-N`. Неизвестные и выключенные филиалы не подменяются общим меню. Изменение филиала очищает корзину. Для продуктов используются существующие карточки и круговая карусель; оформление остаётся демонстрационным, правила совместного заказа ещё не согласованы. Генерация изображения QR-кода пока не добавлена.

### Проверка и границы подтверждения

`npm test`: 26 пройденных тестов. Проверены валидация, авторизация, фото, миграция старой схемы, приватность публичного ответа, независимые цены/наличие, отсечка завтраков, сохранение каталога в временном файловом хранилище с перезапуском обработчика, конфликт двух сеансов и восстановление копии. Протокол private Blob проверен через изолированный адаптер: ETag, запрет перезаписи при создании, обработка конфликта.

В Chromium проверены мобильное меню и режим без подключения. Редактирование блюд/товаров/категорий/филиалов, сохранение и повторная загрузка интерфейса проверены с изолированными ответами API. Эти проверки не подтверждают запись в реальный Vercel Blob. В облачной среде рабочие подключения не предоставлены; удалённое сохранение, вход настоящего владельца и производственная загрузка фото пока не проверены. Публикация приложения не выполнялась.

### Что требуется подключить

1. Существующее закрытое хранилище `sof-menu-admin` к существующему Vercel-проекту `sof-cafe-preview`; проверить доступ SDK и серверные переменные `SOF_SETUP_HASH`, `SOF_SESSION_SECRET`, `BLOB_READ_WRITE_TOKEN` или поддерживаемую авторизацию `BLOB_STORE_ID` в Vercel. Значения вводятся только в серверных настройках. После применения — разрешённый деплой и активация владельца личным ключом, затем проверка сохранения и загрузки фото двумя независимыми сеансами.
2. Реальные названия, адреса, телефоны четырёх филиалов, условия доставки, ассортимент и цены товаров. «От 1000 ₽ доставка» остаётся неуточнённым требованием.
3. Отдельную базу клиентов/заказов, серверный API заказов с пересчётом, проверкой доступности, идемпотентностью и списанием остатков; затем оплату и службы доставки. До этого оформление остаётся демонстрацией.
4. Доступы и серверное хранилище секретов iiko для каждого филиала; реализовать и проверить адаптеры, импорт, стоп-листы и отправку только в разрешённом тестовом контуре. ID организации и терминальной группы можно сохранить в настройках, это не подключение.
5. Настоящие провайдеры входа посетителей: Яндекс ID, SMS и MAX. Сейчас они явно обозначены как неподключённые.
